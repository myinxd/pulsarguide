> [前面那篇](/blog/posts/2026-08-02-end-to-end-autonomous-driving/)里我把 GRPO 当成「训练稳定性」的答案，一句话带过了 PPO 的 Critic 为什么要被砍掉。那篇留下了个漏洞：公式写成了带 KL 的策略梯度，clip 不见了——而 clip 恰恰是整个 PPO 家族唯一的机制。这篇来补。补着补着发现，**GRPO 之后的三次修正，修的全是同一个东西。**

## 1. 先把 PPO 的 clip 讲清楚

大多数教程讲到 PPO 就开始摆公式，然后你就记住了「有个 clip，ε 取 0.2」。但没人告诉你 clip 到底在防什么。

从策略梯度说起。你想最大化期望回报 $J(\theta) = \mathbb{E}_{a \sim \pi_\theta}[R(a)]$，朴素做法是对当前策略采的样本求梯度：

$$\nabla J = \mathbb{E}_{a \sim \pi_\theta}\big[ R(a)\, \nabla \log \pi_\theta(a) \big]$$

问题是：**你采完这组样本、更新了一次参数，这组样本就过期了。** 拿旧策略采的数据去更新新策略，是有偏的。重要性采样修这个偏：

$$\nabla J = \mathbb{E}_{a \sim \pi_{\theta_{old}}}\Big[ \frac{\pi_\theta(a)}{\pi_{\theta_{old}}(a)}\, R(a)\, \nabla \log \pi_\theta(a) \Big]$$

那个比值 $\rho = \pi_\theta / \pi_{\theta_{old}}$ 就是重要性采样比。理论上是无偏的——但**前提是 $\pi_\theta$ 和 $\pi_{\theta_{old}}$ 别差太远**。差太远，比值的方差会炸，一次更新就能把策略推到悬崖下。

PPO 的做法非常工程化：**不修方差，直接限制比值能走多远。**

$$\mathcal{L}^{clip} = \mathbb{E}\Big[ \min\big( \rho \hat A,\ \mathrm{clip}(\rho,\, 1-\epsilon,\, 1+\epsilon)\, \hat A \big) \Big]$$

为什么这个 $\min$ 能刹车？分两种情况：

- **优势为正**（这个动作比平均好）：$\rho$ 涨到 $1+\epsilon$ 以上，$\mathrm{clip}$ 把它压回 $1+\epsilon$，$\min$ 取到常数，梯度归零。**意思是「我觉得这动作好，已经把它的概率提了 20%，够了，别再提了」。**
- **优势为负**（这个动作比平均差）：$\rho$ 跌到 $1-\epsilon$ 以下，同样被压住，不再继续打压。

一句话：**clip 把「单个动作在单次更新里的概率变动」框死在约 $\pm 20\%$。** 它防的不是梯度噪声，是**步子太大**。

这是理解后面一切的钥匙。因为接下来所有的变体，**没有一个动过这个 clip 本身**——除了一个，而它改的是别的东西。

## 2. GRPO：把 Critic 删了，别的照抄

PPO 里那个 $\hat A$ 是优势函数，通常由价值网络（Critic）估：$\hat A = R - V_\phi(s)$。

Critic 的代价很实在：**参数量和策略网络同量级，显存和算力近乎翻倍**。而且它自己也要训练，自己也会估错。在连续高维动作空间里，$V$ 极难学准，估出来的优势方差可能比不用它还大。

GRPO（DeepSeekMath，2024）的想法朴素到有点粗暴：**同一个场景采一组 $G$ 条轨迹，你们之间比一比不就有基线了？**

$$\hat A_i = \frac{r_i - \mathrm{mean}(\{r_j\})}{\mathrm{std}(\{r_j\})}$$

组内均值当基线，组内标准差做归一化。**不要 Critic 了，基线从样本里现算。**

然后把 $\hat A_i$ 塞回 PPO 那个 clip 目标，再加一项对参考策略的 KL：

$$\mathcal{L}_{GRPO} = \frac{1}{G}\sum_{i=1}^{G} \min\Big( \rho_i \hat A_i,\ \mathrm{clip}(\rho_i,\, 1-\epsilon,\, 1+\epsilon)\, \hat A_i \Big) - \beta\, \mathrm{KL}\big(\pi_\theta \,\|\, \pi_{\theta_{ref}}\big)$$

**看清楚：clip 完整保留。** GRPO 省掉的是价值网络，不是稳定性机制。很多人（包括之前的我）把它写成 $\mathbb{E}[A \cdot \log \frac{\pi_\theta}{\pi_{ref}}]$，那是个带 KL 的 REINFORCE，不是 GRPO——少了 clip，也就少了全部的刹车。

还有一处容易混的符号分工：

| 符号 | 出现在哪 | 是什么 | 多久换一次 |
|---|---|---|---|
| $\pi_{\theta_{old}}$ | 只在 $\rho$ 里 | 采样出这批数据的策略 | 每个 batch |
| $\pi_{\theta_{ref}}$ | 只在 KL 里 | 安全基线（通常 SFT 模型） | 全程固定 |

把这两个当成一个东西，公式就会写成上面那种错的样子。

## 3. 上线之后，四个洞同时漏

GRPO 在数学、代码这类任务上跑通了，然后大家发现它有四个毛病。这四个毛病后面催生了三个变体——注意对应关系：

| 洞 | 症状 | 谁补的 |
|---|---|---|
| 熵坍塌 | 策略越来越确定，探索没了，输出千篇一律 | DAPO 的 clip-higher |
| 零方差组 | 一组全对或全错，$\mathrm{std}=0$，优势全 0，梯度没了 | DAPO 的动态采样 |
| 长度偏置 | 错的回答越写越长，因为除以长度让长错答案罚得轻 | DAPO 的 token-level loss、Dr.GRPO 去归一化 |
| token 级比无效 | 每个 token 只采一次，$\rho$ 压根不是有效估计量 | GSPO 改成序列级 |

前三个洞是**症状**，第四个洞是**病理**。这个区别后面会变得很重要。

## 4. DAPO：四个补丁，AIME 从 30 到 50

字节 Seed + 清华 AIR + 港大，2025 年 3 月（arXiv:2503.14476）。名字就是四个改动的缩写：**D**ecoupled Clip **A**nd Dynamic S**a**mpling **P**olicy **O**ptimization。

**① Clip-Higher —— 拆开上下界**

标准 GRPO 两侧都是 $\epsilon = 0.2$。DAPO 把它解耦：下界还是 0.2，上界抬到 **0.28**。

为什么只抬上界？因为熵坍塌的机制是「低概率的探索 token 提不上来」。一个概率 0.01 的 token 想变成正确答案，需要 $\rho$ 涨 100 倍才能给到足够梯度——而 clip 在 1.2 就把它掐死了。**上界抬高，等于给「冷门 token 翻身」留了条缝；下界不动，等于「热门 token 别涨太快」的约束还在。** 不对称是有意的：它只放探索，不放利用。

**② 动态采样 —— 把没梯度的组扔掉**

一组 $G$ 条全对（$r$ 全 1）或全错（$r$ 全 0），$\mathrm{std} = 0$，$\hat A_i$ 全 0，这一步白跑。

DAPO 的做法很直接：**这种组在算梯度之前就过滤掉，然后继续采，直到凑够一个有效 batch。** 代价是采样成本上升，收益是每一步都有真实信号。

这一条在工程上特别值得记，因为它把「训练稳定性」问题转化成了「数据吞吐」问题——而后者好解得多。

**③ Token-level loss —— 改归一化的分母**

GRPO 对每条回答除以自己的长度 $|o_i|$。后果：长回答里每个 token 的权重被摊薄，短回答里被放大。

DAPO 改成整个 batch 所有 token 一视同仁。**直觉是：推理链里那个关键的转折 token，不该因为整条回答长就变得不重要。**

**④ Overlong Reward Shaping —— 截断不该等于答错**

撞到最大长度被截断的回答，GRPO 给的奖励和「完整但答错」一样。模型学到的信号是「反正都是零分」，于是截断样本反而在教它乱写。

DAPO 在长度上限前开一个窗口（论文里是 20480 上限、4096 窗口）做渐进惩罚，让「快超长了」和「超长了」区分开。

**这套配方有多值钱？看消融阶梯**（Qwen2.5-32B，AIME 2024）：

| 累积改动 | AIME 2024 |
|---|---|
| 朴素 GRPO | 30 |
| + 过滤超长样本 | 36 |
| + Clip-Higher | 38 |
| + 软性超长惩罚 | 41 |
| + Token-level loss | 42 |
| + 动态采样 | **50** |

对比 DeepSeek-R1-Zero-Qwen-32B 的 47 分，**训练步数还少一半**。超参：prompt batch 512、组大小 $G=16$、学习率 1e-6、最大长度 20480。

注意最后一格：从 42 到 50，全靠动态采样。**四个补丁里有三个只是把错误信号修正回来，真正把分数顶上去的是「别在没信号的数据上浪费步数」。**

## 5. Dr.GRPO：问题不在补丁，在归一化本身

DAPO 是加法——加四个补丁。Dr.GRPO（Sea AI Lab + NUS，2025 年 3 月，arXiv:2503.20783）是减法，而且减得很不客气。

它的出发点是一句质问：**R1-Zero 那种「回答越训越长」的现象，到底是深度思考，还是目标函数写错了？**

结论：写错了。GRPO 的目标里有两个归一化，各自带一个偏置。

**偏置一：长度归一化 $1/|o_i|$。**

回看 GRPO 那一项 $\frac{1}{|o_i|}\sum_t$。当优势为负（答错了），损失是「负值 × 概率」，除以长度意味着：**答得越长的错误回答，每个 token 分到的惩罚越小。**

翻译成人话：**如果你注定要错，那就错得长一点，罚得轻。** 模型当然会学会这一手。所谓「越长越聪明」的曲线，有相当一部分是在学「怎么更划算地犯错」。

**偏置二：难度归一化 $1/\mathrm{std}$。**

除以组内标准差，等于把不同题目的优势拉到同一尺度。但 $\mathrm{std}$ 小的时候——题目太简单（全对）或太难（全错）——这个除法会把几乎为零的信号放大成正常量级。**结果是：最容易和最难的那批题，被过度加权了。**

Dr.GRPO 的处理：**两个都删掉。** 优势就用 $r_i - \mathrm{mean}(\{r_j\})$，损失就按 token 总数归一化。回到 PPO 那种无偏形式。

效果：Oat-Zero-7B 在 AIME 2024 拿到 43.3%，8 张 A100 训 27 小时。

而且这篇还顺手砸了一个偶像。大家以为「Aha moment」（自我纠错、回头检查）是 RL 涌现出来的。作者去测了**未经 RL 的基座模型**——DeepSeek-V3-Base 在高温采样下本来就会说「等等，我再检查一遍」。**RL 没创造它，只是把它放大了。**

另一条更扎心：Qwen2.5-Math 基座**去掉 prompt 模板后**，五个基准平均涨 30.5 个点。说明它在预训练时就见过大量「问-答」拼接文本，本身已经半 SFT 化了。

**这两条加起来的含义：你以为在测算法，其实在测基座。** 这在驾驶领域同样成立——换个感知预训练权重，RL 阶段的表现可能整个变样。

## 6. GSPO：问题不在归一化，在粒度

到这一步，剧本应该是「再打一个补丁」。但 Qwen 团队（2025 年 7 月，arXiv:2507.18071）掀了桌子：**你们修的都是症状，病根是重要性采样比算在了错误的粒度上。**

它的论证值得逐字读：

> token 级的重要性比，作为重要性采样估计量是**无效的**。因为每个 token 只被采样一次，这个比值根本没法完成分布校正，只会注入高方差噪声——而噪声随回答长度累积，又被 clip 放大，最终可能导致不可逆的模型崩塌。

换个说法：**重要性采样的前提是「同一个样本被采到多次、能统计出分布」，而一个 token 一辈子只出现一次。** 你在用一个统计上不成立的东西当权重。

（这个批评其实也打在 PPO 身上——PPO 在 LLM 上一直这么用。）

GSPO 的改法：**把比值算在整条序列上。**

$$s_i(\theta) = \left( \frac{\pi_\theta(y_i|x)}{\pi_{\theta_{old}}(y_i|x)} \right)^{1/|y_i|}$$

对整条序列的 log 概率差求和、除以长度、再取指数。**这是所有 token 比值的几何平均。** 然后 clip 作用在这一个数上——漂太远的整条回答，直接排除出梯度，而不是逐 token 掐。

**为什么这个改动是对的？因为奖励本来就是给整条回答的。** 优化单元终于和奖励单元对齐了。

代价是一个反直觉的后果：几何平均的数值尺度极小，所以 clip 窗口必须跟着缩小几个数量级——**3e-4 和 4e-4**，对比 GRPO 的 0.2 / 0.27。**看到这个数字别以为抄错了，它是比值定义换了的必然结果。** 直接拿 0.2 套 GSPO，等于完全不 clip。

另外还配了 $\beta = 0$（不要 KL）和 `steps_per_generation = 4`（一个 rollout batch 切四个 minibatch）。

GSPO 的两个工程红利值得一提：

- **MoE 不用 Routing Replay 了。** GRPO 训 MoE 时，训练引擎和推理引擎路由到的专家可能不一致，得把推理时的路由缓存下来「重播」。序列级似然对单个 token 的似然不敏感，这条绕路就省了。
- **对精度差异更宽容。** 可以直接用推理引擎返回的似然做优化，不用训练引擎重算。这对 partial rollout、多轮 RL、训推分离架构是实打实的省。

Qwen3 的 Instruct / Coder / Thinking 三个版本都用它训的。

## 7. 四次修正，修的到底是什么

回到开头那句话。让我把这条线摊平：

| 版本 | 动了什么 | 修的是 |
|---|---|---|
| PPO | 定下 clip | 步子太大 |
| GRPO | 删 Critic，换组内基线 | 省显存与算力 |
| DAPO | 拆上下界、过滤零方差组、改分母、软化截断 | 熵坍塌、空梯度、长度偏置、截断噪声 |
| Dr.GRPO | 删两个归一化 | 同一批偏置，但从根上删 |
| GSPO | 比值从 token 级换到序列级 | 估计量本身无效 |

如果只看表面，这是四次独立的技术演进。但把它们叠在一起，会看到一条更干净的线：

**PPO 之后的所有工作，都在回答同一个问题——「当奖励只给到整条轨迹、而优化却落在更细的粒度上时，怎么把两者对上」。**

DAPO 用四个补丁去凑这个对齐；Dr.GRPO 发现凑的方式本身带偏置，直接删掉；GSPO 干脆把优化粒度抬到和奖励同一个层级。

有意思的是，**没有一次动过 clip 的 ε 语义**——除了 GSPO，而它动 ε 是因为比的尺度变了，不是因为觉得 clip 不重要。**clip 是这条线上唯一没被质疑过的东西。**

## 8. 搬到驾驶上：能搬的和不能搬的

这套东西全是给「可验证奖励 + 离散 token」造的。驾驶两样都不占：奖励是个模型给的连续分数，输出是一条连续轨迹。

那哪些能搬？

**能搬，而且直接有用：动态采样。**

驾驶里同样有「全成功」和「全失败」的场景组：直道巡航，采 8 条轨迹全都不撞，组内方差为零，这一步白跑；极端加塞，8 条全撞，同样白跑。**过滤掉这两类场景继续采**，是个纯粹的正收益——它不改变算法，只改变数据供给。

**能搬，但要换概念：GSPO 的粒度教训。**

驾驶没有 token，但有**去噪步**。扩散规划器每采一条轨迹要跑 T 步去噪——如果你在去噪步的粒度上算重要性比，那就是 GSPO 批评的那个错误，一步不差地重犯一遍：

> 每一个去噪步只被走一次，用它算比值不是重要性采样，是噪声。

正确的做法是把比值算在整条轨迹的似然上。扩散模型的轨迹似然可以算（对数似然的变分上界），只是贵。**这可能是 GSPO 对驾驶最有价值的一句话：先把优化单元对齐到奖励单元，再谈 clip 窗口设多少。**

**能搬，但要重新标定：clip 的 ε。**

$\epsilon = 0.2$ 是离散 softmax 上的经验值。连续动作空间里，策略是高斯或扩散过程，概率密度比的尺度和 softmax 完全不是一回事——同一条轨迹在两个策略下的对数似然差可以是几十，也可以接近零，取决于方差参数化方式。**照抄 0.2 是没根据的，得自己扫。**

**不能搬：token-level loss。**

轨迹上没有 token 这个单位。硬要类比成 waypoint，那就是「按 waypoint 数归一化」——而这正好是 Dr.GRPO 花了一整篇论文批评的长度偏置。**搬之前先想清楚自己在归一化什么。**

**还有一个更根本的问题：这四次修正，一次都没碰奖励。**

LLM 的 RL 能起来，是因为有个 rule-based verifier 能判对错，信号几乎无噪。驾驶没有这个东西——你得训一个奖励模型，而奖励模型会过拟合、会被刷分。前面[那篇](/blog/posts/2026-08-02-end-to-end-autonomous-driving/)里说的 reward hacking，在这里不是脚注，是主要矛盾。

所以我的判断是：**GRPO 家族的四次修正，解决的是「如何用一个有噪声的信号更新策略」；而驾驶的瓶颈在「这个信号到底是什么」。** 前者是优化器问题，后者是目标定义问题。后者不解决，前者的所有精巧设计都会变成「更高效地优化一个错的目标」。

这有点扫兴，但方向大概是对的。
