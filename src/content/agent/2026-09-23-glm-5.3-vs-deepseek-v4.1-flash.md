> 两个都便宜、都强、都撑百万上下文，可真用起来，手感完全是两回事。一个像先动手、自己验、接着改的长工；一个像先想透、再开写的分析师。这不是玄学，是两家对同一个问题押了不同的答案：能力到底从哪来？

---

## 一、先把底子摆清楚

这两家最近的更新几乎撞在一起：智谱 8 月 14 日发 GLM-5.3，DeepSeek 9 月 10 日发 V4.1 Flash。命名上它们不完全是同一档——GLM-5.3 是智谱的旗舰，DeepSeek 的旗舰另有其人——但因为都便宜、都主打 Agent 和编程，实际选型时经常被放在一起比。

| 维度 | GLM-5.3 | DeepSeek V4.1 Flash |
| --- | --- | --- |
| 总参数 / 激活 | 743B MoE / 约 40B | 552B MoE / 输入 8B · 输出 16B |
| 注意力与结构 | MLA + DSA 稀疏注意力 + IndexShare + MTP 投机解码 | Causal-Encoder-Decoder，非对称激活 |
| 上下文 / 输出上限 | 1M / 128K | 1M / 384K |
| 模态 | 纯文本 | 原生多模态（文本 / 图像 / 语音） |
| 推理控制 | 常开，`reasoning_effort` 分 low / high / max | 有推理强度档位 |
| 基座 | **沿用 GLM-5.2，一个参数没重训** | 新架构系列的最小尺寸 |
| 权重 | 开源（GLM-5.3 License） | 未开源 |

两类结构差异一眼能看出性格：GLM 是「容量优先」——一个 743B 的大脑子，每次只唤醒 40B，配上稀疏注意力和投机解码把长上下文的成本压下来；DeepSeek 是「成本优先」——同样是 MoE，但它把输入侧砍到 8B、输出侧放到 16B，明摆着告诉你：读你的 prompt 我要收便宜点，写答案才是我真正烧钱的地方。

## 二、GLM-5.3 的赌注：基座冻住，全部压在环境上

智谱官方博客的开篇第一句就是定调：**「Scaling post-training is all we did for GLM-5.3.」** 没有新的预训练，没有更大的参数，所有跃升都来自后训练阶段把强化学习继续放大——更多环境、更多样任务、更多算力。

为什么敢这么干？这是一笔工程账。重训一个千亿级基座要几万张卡、好几个月；冻住基座意味着下游推理基础设施和算子优化零成本迁移，社区在 GLM-5.2 上做的微调资产还能接着用。当预训练参数规模的边际收益变窄，战场就从「谁的参数多」挪到了「谁的后训练做得更好」。

而他们发现真正的瓶颈已经不是模型，是**环境**。官方原话说得很直白：随着 agent 能力变强，后训练扩展的难点很大一部分从模型转移到了环境。一个有用的训练环境必须可执行、可验证、且贴近真实专业工作——而且得有很多个，不是几个手搓样本。于是有了这套端到端的环境合成管线：

- 研究 agent 从真实工作流里收集任务模式，转成带多步依赖和隐藏状态的可运行长周期环境；
- 判断 agent 亲自试跑每个任务，确认它确实可解，避免坏训练信号混进来；
- 验证器在**不接触参考解**的情况下合成，再用求解轨迹去发现并堵掉「奖励捷径」；
- 每个验证器上线前必须过三道检查：喂正确解要给奖励（oracle）、喂空操作不给奖励、喂半成品也不给奖励。

三道检查听着朴素，但这是整个训练信号可信的前提——只有当验证器「只奖励正确且完整的解」，RL 才不会学出一堆钻空子的花招。

支撑这整套的是两个自研组件。**SAO（Single-rollout Asynchronous Optimization）** 把「凑齐一整批再更新」的老逻辑扔掉，改成单条轨迹级别的异步：模型跑完一条完整轨迹就立刻进缓冲区，训练端马上读走更新，两边彻底解耦。效果是长程训练能稳定跑过 **1000 步**，而传统异步 GRPO 大约 **160 步**就因为策略跑偏崩掉。**slime** 是后训练框架，训练侧用 Megatron、rollout 侧用 SGLang，把训练、rollout、数据缓冲放在同一条数据流上，数学、代码、沙箱、验证器、长程 Agent 环境都能作为「数据生成」接进来，不用为新增任务重建训练循环。这一代它还加了多教师 on-policy 蒸馏（代码教师管代码、数学教师管数学，动态切换加预取，几位教师共用一套资源），并把训练侧和 rollout 侧的 logprob 平均差异压到 **1e-7** 量级——比此前配置小了 99.99% 以上。

落到数字上，GLM-5.2 到 GLM-5.3 在同一副基座上完成了这些跳跃：

| 基准 | GLM-5.2 | GLM-5.3 |
| --- | --- | --- |
| Terminal-Bench 3.0 | 4.6 | 28.3 |
| DeepSWE v1.1 | 46.2 | 66.9 |
| Agents' Last Exam | 23.8 | 28.5 |
| Z.ai Code Bench（Max 档） | 23.4 | 34.5 |

最后一行尤其值得看：GLM-5.2 用 **96K** 输出 token 拿到 23.4，GLM-5.3 只用 **75K** token 就拿到 34.5。分数上去的同时 token 反而更省——这说明它的长程轨迹更短、更少绕路，不是靠堆思考量换来的分。

## 三、DeepSeek V4.1 Flash 的赌注：把架构当成成本接口重画

如果说 GLM 是「把模型训成好员工」，DeepSeek 的思路更像「重新设计工位」。V4.1 Flash 用了全新的 Causal-Encoder-Decoder 结构，关键特征是输入输出不对称：总参数 552B 的 MoE，**输入侧只激活 8B，输出侧激活 16B**。这直接对应推理的真实成本曲线——读 prompt 是一次性开销，写出来才是持续烧钱的部分，于是它把「理解上下文」的价格压得远低于「生成回答」。

配套的还有 KV Cache。官方口径是相比初代模型缩小 **437 倍**，落到硬件上 HBM 需求降到 1/4、SSD 需求降到 1/8。对 Agent 场景这是质变，因为工具调用和长程任务里每一轮都要重读几十 K 的上下文，缓存成本往往占大头。此外它是**原生多模态**——文本、图像、语音统一在架构内部处理，而不是给文本模型外挂一个视觉扩展包，上下文 1M、输出上限 384K。

这些都指向同一个结果：便宜、快。Artificial Analysis 的独立测试里，V4.1 Flash 综合智能 40 分、输出速度 197 tok/s，**每个任务只花约 0.27 美元**，而 GLM-5.3 和 Kimi K3 都在 2 美元上下——差了大约 7 倍。它的血统也决定了手感：DeepSeek 的 R1 家族是开源推理模型的鼻祖，所以 V4.1 Flash 在数学、逻辑、多步分析上明显高于自己的价位段。

代价同样清楚：**它想太多**。AA 的数据显示 V4.1 Flash 平均每个任务生成约 **89,000 个 token**，比自家上代 V4 Pro 多 62%，部分抵消了价格优势。这就是典型的「用时间和 token 换质量」的过度推理倾向，实际使用时值得用推理强度档位往下压一压。

## 四、同一批基准上，谁赢谁输

把两边的公开成绩放到一起看会有点反直觉。DataLearner 汇总了 18 项两边都有结果的基准：**DeepSeek V4.1 Flash 赢 12 项，GLM-5.3 赢 6 项**。但赢的位置分布很有意思：

| 类别 | 基准 | DeepSeek V4.1 Flash | GLM-5.3 |
| --- | --- | --- | --- |
| 终端 / Agent | Terminal-Bench 2.1 | **90.6** | 83.9 |
| 终端 / Agent | Terminal-Bench 3.0 | **30.0** | 28.3 |
| 终端 / Agent | Agents' Last Exam | **31.8** | 28.5 |
| 编程 | DeepSWE | **74.2** | 68.96 |
| 编程 | NL2Repo-Bench | **65.4** | 58.0 |
| 编程 | SciCode | 51.9 | **59.0** |
| 专业知识 | GDPval-AA v2 | 1632 | **1658** |
| 专业知识 | AA-Briefcase | 1424 | **1511** |
| 科学推理 | CritPt | 14.3 | **19.1** |
| 科学推理 | GPQA Diamond | 90.9 | **91.7** |
| 长上下文 | AA-LCR | **84.0** | 79.7 |
| 安全 | CyberGym | **88.1** | 84.5 |

规律很清晰：**GLM-5.3 拿下的是科学推理和专业知识题**（SciCode、CritPt、GPQA Diamond、GDPval-AA v2、AA-Briefcase），这些恰好是它后训练环境里「像真实专家工作」的那一类；**DeepSeek 反而在终端和 agent 类基准上常常领先**（Terminal-Bench、DeepSWE、Agents' Last Exam），这跟「GLM 专攻长程 Agent」的直觉是反的。

> 口径提醒：这些是各家发表的结果，不是同一批复跑，推理档位也可能不同；GLM-5.3 的「Terminal-Bench 3.0 开源 SOTA」是在开源权重模型范围内的说法，V4.1 Flash 未开源，两者不在同一擂台。看趋势可以，别当精确排名。

## 五、根因：两种「能力从哪来」的假设

把上面两条线合起来看，分歧其实只有一个：**额外能力该从哪里要？**

智谱的答案是「环境」。他们公开的判断是，总参数在「足够装下世界」之后就不是关键了，能力来自每次前向的有效深度、以及压倒性的后训练投入。所以 GLM-5.3 把一个 743B 的基座冻住，把一个月的时间和全部算力砸进可执行、可验证的长程环境里。这样训出来的模型，行为上天然带着「先动手、自己验、接着改」的惯性——它是在「任务能不能被机器验收」这个奖励信号里长起来的。

DeepSeek 的答案是「接口」。它相信同样的能力可以在低得多的成本上兑现，于是重画了注意力、激活结构和缓存定价——非对称激活、437 倍 KV 压缩、原生多模态。这样训出来的模型，行为上更像「想透再写」的分析师：推理血统深、长上下文强、技术文干脆，但会不自觉地开启超长思考。

一句话总结：**一个把预算花在让模型学会在真实环境里把活干完，一个把预算花在让模型想得又长又便宜。** 你要比的不只是分数，是这两种姿态哪种更贴你的任务。

（顺带一提，智谱这次用的多教师 on-policy 蒸馏，和我们此前拆过的 ME-VLM 是同一招——同一时间点、不同实验室，都把「多个专才教师蒸馏进一个学生」当成了把异构能力塞进单模型的标准做法。这条线值得单独跟。）

## 六、如果你要比的是 Flash 对 Flash

上面比的其实是 GLM-5.3 旗舰。真要跟 DeepSeek V4.1 Flash 对位，应该看 **GLM-5.3-Flash**：它和 GLM-5.3 共享「后训练扩展」这条路线，但分支点不同——GLM-5.3 是在 744B 老基座上继续加环境，GLM-5.3-Flash 则是**从头训了一个全新的 320B 基座**，在架构层面先围绕效率重设计，再做后训练对齐，而且是 GLM-5 系列首个原生多模态模型，MIT 许可。价格上也更贴近：GLM-5.3-Flash 输出约 $0.25/1M，DeepSeek V4.1 Flash 约 $0.60/1M。

所以严格来说：**旗舰比旗舰是「环境 vs 接口」，Flash 比 Flash 是「新底座 + 原生多模态 vs 非对称激活 + 便宜」**。命名容易混，选型前先确认自己调的是哪一个。

## 七、怎么选

| 你的场景 | 更合适的一侧 |
| --- | --- |
| 长程终端任务、需要机器验收的自动化 | GLM-5.3 |
| 工具调用可靠性、结构化改写、格式服从 | GLM-5.3 |
| 科学推理、专业领域判断题 | GLM-5.3 |
| 数学、逻辑、多步分析 | DeepSeek V4.1 Flash |
| 一次塞进大量文件的长上下文调试 | DeepSeek V4.1 Flash |

## 八、三条实践提醒

第一，**速度数据别信单一来源**。我们看到的几组结果互相打架：OpenRouter 的复现探针测出 GLM-5.3 约 337 tok/s、DeepSeek 约 78 tok/s（GLM 快 4.3 倍）；OrcaRouter 的实测却是 DeepSeek 214 tok/s、GLM 83 tok/s（DeepSeek 快 2.6 倍）；Artificial Analysis 又是第三个数字。吞吐和延迟高度依赖服务商、量化、并发和负载，换一家托管商结论可能就翻转。真要选型，自己在目标供应商上跑一遍。

第二，**首 token 延迟的值和「推理常开」强相关**。GLM-5.3 的思考过程是常开的（可用 `reasoning_effort` 调档），这意味着它天然比「按需思考」的模型更慢进入输出。交互式场景要么压档位、要么把这类模型放到异步队列里，别拿它做秒回的对话前端。

第三，**别二选一，路由是标准动作**。两家的 API 都是 OpenAI 兼容，切模型只改一个字符串。理性的做法是把批量、简单、高并发的流量交给便宜快的那侧，把需要长程验收或专业判断的留给另一侧，然后拿自己的 100 条真实 prompt 跑一遍质量加权成本，用数据决定比例。这个套路我们在此前聊共享管道限流那篇里也提过——今天两家都便宜到这个地步，路由的收益比任何时候都大。
