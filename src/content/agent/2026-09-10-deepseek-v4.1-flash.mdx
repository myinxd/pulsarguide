# DeepSeek V4.1 Flash 发布：用非对称架构把推理成本打下来，顺手把 Pro 挤下水

> 9 月 10 日，DeepSeek 正式发布 V4.1 Flash。官方给的定位很直白：这是全新模型结构系列里**最小尺寸**的模型，原生多模态，然后在性能、费用、速度、总用时上**全面超越 V4 Pro**。一个「小弟」把「旗舰」按在地上，这件事本身比任何单点参数都值得写——因为它背后是一套正在成形的成本哲学：用架构创新，而不是堆参数，去换「又强又便宜」。

---

## 一、不是常规升级：全新 Causal-Encoder-Decoder 架构

V4.1 Flash 最大的变化不是参数涨了，而是**结构换了**。

DeepSeek 这次用了一个叫 **Causal-Encoder-Decoder** 的结构，关键特征是「输入和输出不对称」：模型总参数是 552B 的 MoE，但**输入侧只激活 8B，输出侧激活 16B**。

「不对称」听起来怪，但想一下推理的真实成本结构就明白了：读 prompt 是一次性开销，写出来才是持续烧钱的部分。把输入压到 8B、输出放到 16B，意味着你为「理解上下文」付的钱远少于「生成回答」——而大多数 Agent 任务的瓶颈恰恰是前者：超长 system prompt、塞满工具定义的上下文、动辄几十轮的历史。

这不是 V4 系列的小修小补。KOCPC 的报道把它称为「V4 系列自今年 4 月发布以来最大的一次架构级更新」，而且**原生多模态**——和 8 月 21 日那个「给文本模型外挂视觉扩展包」的 V4 Flash Vision Exp 不同，V4.1 Flash 把文本、图像、语音统一在模型架构内部处理，而不是拼装出来的。

## 二、非对称激活：你只为 8B / 16B 付费

MoE 的常识是「总参数吓人，激活参数才是你真正付的钱」。V4.1 Flash 把这个常识推到了极致——用 552B 的总容量做知识库，但每次推理只点亮 8B（输入）/ 16B（输出）的神经元。

对比一下量级：上一代 V4 Flash 的输入激活远高，而 V4.1 Flash 把输入侧砍到 8B，直接导致两件事——首 token 延迟下降，以及长上下文场景下的缓存成本大幅下降（下一节细说）。

这也解释了为什么官方敢问出那个问题：在 beta 问卷里，DeepSeek 直接问开发者「**V4.1 Flash 能否完全替代生产环境里的 V4 Pro？**」——如果小尺寸就能顶替大 Pro，那 Pro 这条产品线存在的意义就被釜底抽薪了。

## 三、KV Cache 压缩 437 倍：长上下文 Agent 的隐性成本被砍

这是我最想单独拎出来说的一点，因为它直接击中 Agent 场景的痛点。

DeepSeek 官方给出的数据是：相比**初代模型**，KV Cache 已经缩小了 **437 倍**；落到硬件上，对 HBM 的需求降到 1/4，对 SSD 的需求降到 1/8。

为什么这件事对 Agent 是质变？因为在工具调用、长程任务里，**缓存命中的费用往往占大头**——模型每轮要重读一遍几十 K 的上下文，KV Cache 越大，单次调用的隐性成本越高。V4.1 Flash 把上下文存储压下去，等于直接削掉了 Agent 类任务最贵的那块成本。

用一张表把这次的几个关键数字收一下：

| 指标 | V4.1 Flash | 对比参照 | 变化 |
| --- | --- | --- | --- |
| 总参数 / 激活 | 552B MoE / 输入 8B·输出 16B | V4 Pro 大模型 | 非对称激活 |
| KV Cache（相对初代） | 缩小 437 倍 | 初代 V 系列 | HBM 1/4、SSD 1/8 |
| 持续吞吐 | ~355 tok/s | V4 Pro ~63 tok/s | **5.7×** |
| 首 token 延迟 (TTFT) | 178 ms | V4 Pro 766 ms | **↓ 77%** |
| 输出价格（9/10 起） | $0.60 / 1M tokens | V4 Pro 约 $1.74 / 1M | 低一截 |

> 速度与延迟数据来自社区实测（@riba2534 等），官方未单独发布完整 benchmark；「全面超越 V4 Pro」为 DeepSeek 官方表述，社区编码与速度测试整体印证。

## 四、数据说话：Flash 全面超越 Pro

抛开架构，落到体验上的数字很硬：

- **速度**：连续生成稳定在 355 tok/s，峰值冲到 427 tok/s；比 V4 Pro 持续吞吐高 5.7 倍，首 token 延迟砍掉 77%。一个 1500 token 的双向链表 LRU 实现只用了 4.4 秒，而 V4 Pro 要 24.7 秒。
- **能力**：官方称在性能、费用、速度、总用时**四项全维度超越 V4 Pro**。社区里有人拿 Three.js 场景测试，评价是 V4.1 Flash 和原 V4 比「天差地别」，特别在视觉丰富度和场景组合上。代价是偶尔「想太多」——同一个七奇迹 Three.js 测试，它花了约 2 小时、$2.60 才跑完两轮，竞品约 30 分钟，但成品质量明显更好。这是典型的「用时间和钱换质量」的过度推理倾向，值得用推理强度档位压一压。
- **原生多模态 + 1M 上下文**：文本、图像、语音统一输入，上下文窗口 1M，输出上限 384K。

API 侧几乎零迁移成本：把模型名改成 `deepseek-flash` 即可。旧的 V4 Flash 和 V4 Flash Vision Exp 已路由到 V4.1 Flash，官方同时计划有序下线 V4 Pro。

## 五、把 Pro 逼下线的商业逻辑

把这几件事连起来看，V4.1 Flash 的打法很清楚：**用 Flash 的价格，卖 Pro 的能力。**

过去 DeepSeek 的产品线是「便宜的 Flash + 贵的 Pro」双轨，Pro 靠能力溢价。现在 Flash 在能力上追平甚至反超 Pro，价格还维持低位（9/10 起再降一轮：缓存输入从 $0.000075 降到 $0.00003 / 1M，未命中输入从 $0.22 降到 $0.15 / 1M，输出 $0.60 / 1M），那 Pro 就变成了「同能力但更贵」的尴尬存在——下线只是时间问题。

这跟 DeepSeek 近期的融资节奏也对得上：传闻 500 亿人民币融资、梁文锋个人出资 200 亿。当低成本模型能吃掉高价模型的大部分任务，「Flash 价、Pro 力」就不只是技术迭代，而是商业化路径的关键一步——企业市场里，价格竞争力往往比绝对能力上限更决定采购。

它也呼应了 DINOv3 系列那句「接口先于能力」：DeepSeek 做的事，本质是把推理的接口（KV Cache、激活结构、缓存定价）重新设计了一遍，让同样的模型能力能以低得多的成本兑现。架构创新和接口设计，往往比堆参数更能决定能力能不能落地。
