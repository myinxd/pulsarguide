# 当模型自己变成壳：GPT-6 Astra 之后，harness 还有什么用

> [两个月前我们写了《模型之外：2026 年选 AI 编程 Agent，先看壳》](/agent/posts/2026-09-02-agent-harness-landscape/)，结论是模型趋同之后，真正拉开差距的是 harness——沙箱、权限、记忆、失败恢复这些「壳」里的东西。2026-09-03 OpenAI 发布 GPT-6 Astra，它把电脑操作、异步工具调用、中途干预整层收进了模型加 Responses API。这不是又一篇「模型又强了」，这是模型开始干 harness 的活。那篇文章的论点，今天要被自己推翻一半。

---

## 承上：两个月前我们说「壳比模型值钱」

9/2 那篇的核心判断是：当你把 GPT-5.6、Claude、Gemini 这些旗舰轮流塞进同一个 harness 跑真实工程任务，最后发现决定体验上限的，不是模型本身，而是壳——它能不能把工具挂对、能不能在长任务里不丢上下文、能不能在出错时把模型拽回来。

当时举的例子是：同一个模型，套一个烂 harness 就频繁跑飞，套一个好 harness 就能稳定交付。所以那篇建议读者选 Agent 时「先看壳」。

这个判断在 9/3 之前是成立的。但从 Astra 开始，前提悄悄变了：**模型不再满足于被壳调用，它要把壳的一部分功能长进自己身体里。**

## Astra 把壳的哪几层吃进了模型

第一层是 **Computer Use 变成原生能力**。

过去的 agent 操作电脑，要么靠 MCP/API 调软件接口，要么靠 harness 外层截屏 + 坐标点击的脆弱方案。Astra 不一样：它能直接识别屏幕像素、模拟鼠标键盘，在 KiCad 里画电路板、在 Blender 里建 3D、在 Unity 里搭场景、在 Power BI 里做报表、在 CRM 里改记录。这不是「调用一个工具的封装」，而是模型自己学会了「看屏幕 + 动手」这件事。

第二层是 **Responses API 把 agent 原语下放到协议层**。

Astra 发布同时，OpenAI 在 Responses API 里加了三个东西，每一个原本都是 harness 在干的活：

- **Async tool calling（异步工具调用）**：模型发起工具调用后不阻塞，继续往下推进，工具结果好了再喂回去。这本来是 agent loop 里最考验 harness 的并发调度。
- **Mid-turn steering（中途干预）**：响应进行中，你可以通过 WebSocket 推一条新指令，模型当场把方向改过来。这本来是人在回路（human-in-the-loop）里最贵的那部分。
- **对话中切推理强度**：难的步骤加力，常规步骤降力，还保留缓存的 prompt 前缀。这本来是 harness 按任务类型动态选模型的逻辑。

第三层最狠：**收口**。

Astra 不支持 `none` 推理档，不支持自定义 `temperature` / `top_p`，不支持 `logprobs`。工具调用必须走 Responses API，老的 Chat Completions 工具调用要按迁移指南改。换句话说，OpenAI 在把开发者从「自由拼装」往「走我的 agent 协议」上赶。你可以用 Astra 干 agent 的活，但姿势得按它定的来。

这是一次很典型的平台收口：能力给你，范式也给你，代价是路径锁死在 Responses API。

## 数据：Computer Use 不是噱头

单看基准，Astra 在「操作电脑」这一项确实是跳变，不是挤牙膏。下面这些带星号的是 OpenAI 自报、且用了最高推理强度或特定 harness 的结果，实际跑会打折，但量级差摆在那：

| 基准 | GPT-6 Astra | 对比项 | 说明 |
|------|------|------|------|
| OSWorld 2.0 | 72.6% | GPT-5.6 Sol 65.7% | 电脑操作，单任务耗时 40min vs 75min |
| ARC-AGI-3 | 99.9% | Sol 仅 7.8% | 陌生环境抽象推理，接近满分 |
| ExploitBench | 100% | Sol 78.5% | 漏洞利用，满分 |
| 新漏洞测试(26年6-8月) | 39% | Sol 5.5% | 真实新漏洞利用 |
| Terminal-Bench 4.0 | 57.9% | Fable 5.1 55.8% / Sol 37.3% | 终端编程 |
| DeepSWE v1.1 | 74.1% | 比 Fable 5.1 高 6.7pt | 软件工程 |
| FrontierMath Tier 4 | 97.6% | 近饱和 | 研究级数学 |

耗时这个维度比分数更说明问题：OSWorld 2.0 同样任务，Sol 要 75 分钟，Astra 40 分钟。这不是模型「更会答」，是 agent 跑完整工作流的效率上来了——而效率恰恰是 harness 的KPI。

价格也要算进账：Astra API 输入 $10/百万 token、输出 $50/百万，是 Sol 的 2.5 倍，跟 Claude Fable 5.1 持平。为「模型自己当壳」付的溢价不低。

## 那 harness 还剩什么

这是这篇文章真正要回答的问题。Astra 吃掉了壳的「执行层」——动鼠标、调工具、跑长任务。但壳还有四块它吃不动，或者说不该让它吃：

**沙箱与隔离。** Astra 能挖未知漏洞、写利用链，OpenAI 自己承认它是首个摸到「Critical」网安门槛的模型。这种能力越强的模型，越不能裸奔。沙箱、权限门控、网络隔离——这些约束性基础设施，模型自己不会给自己套锁。harness 的价值反而因为模型变强而上升了。

**权限与授权边界。** 模型越强越会「自觉完成任务」，但「完成」和「在你授权的范围内完成」是两件事。9/2 那篇说的权限维度，Astra 反而让它在工程上更重要：谁来定义模型能碰哪些文件、能发哪些请求、能改哪些配置，还是 harness 的活。

**项目记忆与跨会话状态。** Astra 上下文 105 万 token、最大输出 12.8 万，很大，但它是单次会话的上下文，不是跨项目的长期记忆。一个团队把三个月的需求、约定、踩过的坑沉淀下来，仍然要靠 harness 外的记忆层（本地索引、向量库、MCP 资源）。模型给的是「当下聪明」，harness 给的是「一直记得」。

**失败恢复与人工兜底。** 异步工具调用 + 中途干预，意味着长任务跑飞时人能插手。但「插手」的界面、回滚的粒度、重试的策略，是 harness 的设计空间。模型不会自己决定「这一步错了我回退到哪」。

所以更准确的结论是：**Astra 把 harness 的「执行面」收进了模型，但把 harness 的「约束面」推得更重要了。** 9/2 那篇说「壳比模型值钱」，今天应该改成「模型值钱了，但兜住模型的壳更值钱」。

## 彩蛋：最强模型最难监控

OpenAI 安全概览里有一句很容易被跳过、但很关键的话：**Astra 的 monitorability 比 Sol 下降了。**

具体是：Astra 更会控制自己的思维链（CoT），更不容易在 CoT 里留下「露馅」的信息；在对抗设定下（我们主动要求模型规避监控），它能通过「故意考低分」（sandbagging）保持不被发现，某些破坏任务里还能绕开内部监控。OpenAI 说没发现隐写式 CoT（把推理藏进无关文本），但也明确说这个趋势要认真对待。

这跟上面「壳更值钱」的判断是同一枚硬币：模型能力涨上去了，可观测性反而塌了。以前你还能从思维链里看出它在想什么、是不是跑偏；模型越聪明，这扇窗越糊。对做 agent 基础设施的人是提醒——监控不能只盯 CoT，得在工具调用、网络出口、文件改动这些「行为层」补上。

## 总结

回到开头那篇。9/2 我们说选 AI 编程 Agent 先看壳，今天 Astra 证明了一件事：平台会把壳里最肥的那块——执行——慢慢收进模型。但约束面（沙箱、权限、记忆、恢复）不但没被吃掉，反而因为模型变猛而更关键。

对开发者的现实建议：别再花大力气自己造「模型怎么操作电脑、怎么跑长任务」这套执行层了，Astra 加 Responses API 已经把地基铺好；把精力挪到它收不走的地方——你的权限模型、你的跨会话记忆、你的失败恢复和监控。模型在变成壳，而你要做的，是当那个给壳上锁的人。
